Rate Limit Lab: Fixed Window vs Sliding Window

This lab shows that a fixed window can allow a boundary burst, then uses a sorted-set sliding window to count requests across a rolling interval.

Break modeFixed window. Requests before and after a boundary each see a fresh counter.
Fix modeSliding window. Recent timestamps remain counted after the clock boundary.
SmoothnessThe sliding window prevents 2x boundary bursts, but still allows a burst up to the limit.

Redis Commands

INCR key

Atomically increments an integer counter. Used by the fixed-window limiter.

EXPIRE key seconds

Sets a TTL on the fixed-window counter so old window keys disappear.

ZADD key score member

Adds one request timestamp to the sorted set. Score is request time in milliseconds.

ZREMRANGEBYSCORE key 0 cutoff

Deletes request timestamps older than the rolling window.

ZCARD key

Counts how many request timestamps remain after cleanup.

PEXPIRE key ms

Applies a millisecond TTL to the sliding-window sorted set.

EVAL script keys args

Runs the limiter check and update atomically on the Redis server.

Fixed-Window Lua

local count = redis.call('INCR', key)
if count == 1 then
  redis.call('EXPIRE', key, windowSec * 2)
end
if count > limit then return {0, count, remaining} end
return {1, count, remaining}
winStart = nowSec - (nowSec % windowSec)

Rounds time down to a clock-aligned window. This is why the boundary burst exists.

key = KEYS[1] .. ':' .. winStart

Creates one Redis counter per window start.

INCR

Counts this request in the current fixed window.

EXPIRE

Sets cleanup TTL only when the counter is first created.

return {0 or 1, count, remaining}

Returns allow/deny, current count, and seconds until reset.

Sliding-Window Lua

redis.call('ZREMRANGEBYSCORE', key, 0, now - windowMs)
local count = redis.call('ZCARD', key)
if count >= limit then return {0, count} end
redis.call('ZADD', key, now, uid)
redis.call('PEXPIRE', key, windowMs)
return {1, count + 1}
ZREMRANGEBYSCORE

Removes requests that are older than the rolling window.

ZCARD

Counts requests still inside the window.

count >= limit

Denies before adding this request if the window is already full.

ZADD

Records the accepted request with a unique member id.

PEXPIRE

Cleans up the key after activity stops.

Run Targets

make break

Fixed window. Look for both phases allowed and total allowed above the configured limit.

make test

Sliding window. Look for phase-2 denies because phase-1 timestamps are still inside the window.

make load

Larger sliding-window run with a higher limit.

Production Notes

  • Fixed window is simple, but it allows boundary bursts.
  • Sliding window prevents boundary bursts, but it is not a strict smooth limiter.
  • For smooth spacing, use GCRA or a leaky-bucket style limiter with next_allowed_at or theoretical arrival time.
  • Use server-side time or consistent app time when multiple app instances apply the same limiter.
